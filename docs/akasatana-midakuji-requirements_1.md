# あかさたなみだくじ 要件定義書

## 1. サービス概要

**サービス名**: あかさたなみだくじ

ライブ配信中のDJが、即興お題を生成するためのWebツール。

**出力フォーマット**

```
{修飾語}{ユーザ名}の{行}
例: セクシーな太郎のさしすせそ
    謎の花子のたちつてと
```

生成されたお題を元に、DJが即興であいうえお作文・トークを行うことを想定する。

---

## 2. 利用シーン・前提

- 主な利用者は**配信中のDJ本人**。PC・スマホでツール画面を見ながら操作する
- リスナー名を都度手入力する。名前はアカウント情報を一切参照しない
- 1回の配信で複数回引くことを想定（連続利用の快適さが重要）
- 結果は**配信画面に映る／読み上げられる**ことを前提に、視認性を最優先とする

---

## 3. 機能要件

### F-01 ユーザ名入力（必須）

| 項目     | 仕様                                                           |
| -------- | -------------------------------------------------------------- |
| 入力方式 | テキスト入力（手入力のみ）                                     |
| 文字数   | 1〜16文字。超過分は入力不可                                    |
| 未入力時 | 引くことは可能。プレースホルダ的に「あなた」を使用             |
| 保持     | 引いた後も入力値はクリアしない（同じ人で連続して引けるように） |
| 消去     | 入力欄内にクリアボタン（×）を配置                              |

### F-02 カテゴリ選択（必須）

| 項目     | 仕様                                                                           |
| -------- | ------------------------------------------------------------------------------ |
| UI       | トグル式のボタン群。**複数選択可**                                             |
| 初期状態 | `defaultOn: true` のカテゴリが選択済み                                         |
| 全OFF時  | 全OFFは許可しない。最後の1つはOFFにできない（またはOFF操作時に全ON扱いへ戻す） |
| 保持     | 選択状態を localStorage に保存し、次回起動時に復元                             |
| 抽選対象 | 選択中カテゴリの修飾語をすべて1つのプールにまとめて抽選                        |

### F-03 抽選ロジック（必須）

1. 選択中カテゴリの修飾語プールから1件をランダム抽出
2. 行マスタから**重み付きランダム**で1件を抽出
3. 結果を組み立てて表示

**連続重複の回避**

- 修飾語: 直近2回に出たものを候補から除外する（プールが3件未満の場合は除外しない）
- 行: 直前1回に出たものを候補から除外する

### F-04 行の重み付け（必須）

「わをん」は物理的に成立しにくいため出現率を極端に下げ、**出たときにレアとして盛り上がる**設計にする。

| 行  | ラベル     | weight | 備考                             |
| --- | ---------- | ------ | -------------------------------- |
| a   | あいうえお | 100    |                                  |
| ka  | かきくけこ | 100    |                                  |
| sa  | さしすせそ | 100    |                                  |
| ta  | たちつてと | 100    |                                  |
| na  | なにぬねの | 100    |                                  |
| ha  | はひふへほ | 100    |                                  |
| ma  | まみむめも | 100    |                                  |
| ya  | やゆよ     | 40     | 3文字。やや難                    |
| ra  | らりるれろ | 100    |                                  |
| wa  | わをん     | 3      | **レア**。約0.36%（≒280回に1回） |

- weight はデータファイル側で調整可能にすること（ハードコードしない）
- `rare: true` の行が出た場合、**専用の演出**を発火させる（後述 F-06）

### F-05 抽選演出：あみだくじ（必須）

**あみだくじで決めるのは修飾語（〇〇な）のみ。行（△△△△△）はあみだの対象外とする。**
両方をあみだにすると演出時間が倍になり、配信のテンポを損なうため。

#### 5-1. あみだの構成

| 項目       | 仕様                                                                                    |
| ---------- | --------------------------------------------------------------------------------------- |
| 縦線の本数 | **4本**（固定）。3本では選択肢が乏しく、5本以上ではスマホ幅で下端の修飾語が読めなくなる |
| 横線       | ランダム配置。同一の高さで隣接する横線が重ならないこと                                  |
| 上端       | 選択用の番号（1〜4）を表示                                                              |
| 下端       | **修飾語4件をすべて可視状態で表示する**（後述）                                         |

#### 5-2. 下端の修飾語は必ず「見せる」

抽選候補となる修飾語4件を、あみだの下端にあらかじめ表示する。伏せてはならない。

理由:

- 伏せると縦線がどれも同じに見え、**開始位置の選択が完全に無意味になる**。あみだくじの形をした乱数ボタンに堕する
- 見えていることで、リスナーがコメントで「3番！」と指定する動機が生まれる
- 外れた選択肢が見えているため、「2番が良かったのに」というリアクションが発生する。**ハズレが見えていること自体が盛り上がりの燃料になる**

実装方針:

1. 選択中カテゴリのプールから修飾語を4件抽出（重複なし、F-03の連続重複回避を適用）
2. 4件を下端にランダム配置
3. 横線をランダム生成
4. ユーザが上端の番号を選択 → たどった先が結果

※ 先に結果を決めてから逆算してあみだを生成する方式でも可。ただし下端4件は必ず実在の候補であること。

#### 5-3. タイミング設計：2拍構成

修飾語と行を同時に出してはならない。**一拍おいて行を落とす。**

```
1拍目: あみだをたどる  → 「セクシーな太郎の…………」
2拍目: 間をおいて確定  → 「さしすせそ！」
```

この設計を採る理由は、**難易度を決めているのは修飾語ではなく行**だから。修飾語が確定した時点でDJは身構えるが、まだ何をやらされるかは分からない。そこに行が落ちる。フリとオチの構造になる。
また、レア行「わをん」が最後に単独で落ちてくることで、レア演出の効果が最大化される。

#### 5-4. 演出時間

**総演出時間は 4.0 秒に固定する。** 引いた回数による可変速度は実装しない。

内訳（目安。定数として一箇所にまとめ、調整可能にすること）:

| フェーズ                 | 時間 |
| ------------------------ | ---- |
| 線をたどるアニメーション | 2.4s |
| 修飾語の確定・強調表示   | 0.4s |
| 間（ため）               | 0.6s |
| 行の落下・確定           | 0.6s |

#### 5-5. その他

- 演出は**スキップ可能**（画面タップで即座に最終結果を表示）
- `prefers-reduced-motion` が有効な場合はアニメーションを省略し、結果を即時表示する

### F-06 結果表示（必須）

- **画面の大部分を占める大きさ**で結果を表示する。配信画面越しに読める文字サイズを確保（viewport幅に応じた可変サイズ、最小でも 28px 相当）
- 表示要素: 「{修飾語}{ユーザ名}の{行}」の全文
- 修飾語部分と行部分は、F-05の2拍構成に対応して**段階的に出現**させる
- 補助表示として、行のかな（例: さ・し・す・せ・そ）を一覧で並べる（作文の手がかりになるため）
- **レア演出**: `rare: true` の行が出た場合、通常と明確に異なる視覚表現（色変化・パーティクル・「激レア」ラベル等）を付与する。行が単独で落ちる2拍目に発火させること
- 「もう一度引く」ボタンを結果画面に配置し、1タップで次を引ける導線にする

### F-07 履歴（必須）

- 直近20件の結果を localStorage に保存
- 折りたたみ可能なリストで表示（デフォルトは閉じた状態）
- 表示項目: 結果全文、引いた時刻
- 全件クリアボタンを設置（確認ダイアログあり）

### F-08 設定（任意・優先度中）

- 履歴の全削除
- レア行（わをん）の出現ON/OFF切り替え
- 効果音のON/OFF（音を実装する場合）

### F-09 結果コピー（任意・優先度低）

- 結果テキストをクリップボードにコピーするボタン

### F-10 名前履歴（任意・優先度低）

- 過去に入力した名前を最大10件保持し、タップで再入力できる
- 手入力が前提のため必須ではないが、同一リスナーを繰り返し指名する場合に有用

## 4. データ構造

修飾語・行のマスタは**単一のJSONファイル**として分離し、コードを触らずに差し替え可能にすること。

```json
{
  "version": 1,
  "categories": [
    {
      "id": "sexy",
      "label": "セクシー",
      "emoji": "💋",
      "defaultOn": true,
      "modifiers": ["セクシーな", "色っぽい", "夜の顔をした"]
    },
    {
      "id": "emo",
      "label": "エモい",
      "emoji": "🌙",
      "defaultOn": true,
      "modifiers": ["エモい", "泣きながら走る", "青春を引きずった"]
    },
    {
      "id": "surreal",
      "label": "シュール",
      "emoji": "🌀",
      "defaultOn": false,
      "modifiers": ["謎の", "宇宙から来た", "説明のつかない"]
    }
  ],
  "rows": [
    {
      "id": "a",
      "label": "あいうえお",
      "kana": ["あ", "い", "う", "え", "お"],
      "weight": 100
    },
    { "id": "ya", "label": "やゆよ", "kana": ["や", "ゆ", "よ"], "weight": 40 },
    {
      "id": "wa",
      "label": "わをん",
      "kana": ["わ", "を", "ん"],
      "weight": 3,
      "rare": true
    }
  ]
}
```

### 重要な設計方針

**`modifiers` には接続語を含めた完成形を格納する**

「セクシー**な**」「かわい**い**」「**謎の**」「泣きながら走る」のように、名前の直前に来る形はそのまま文字列として持つ。プログラム側で助詞を付与してはならない。これにより形容動詞以外の表現（い形容詞・名詞＋の・動詞連体形）も自由に登録できる。

**表示は `modifiers[i] + userName + "の" + rows[j].label` で単純結合する**

## 5. 画面構成

単一画面（SPA・1ページ完結）。上から順に:

1. **ヘッダー** — ロゴ／サービス名
2. **名前入力欄**
3. **カテゴリ選択ボタン群**
4. **「引く」ボタン** — 画面下部に大きく固定配置。親指で押せる位置
5. **演出エリア** — 抽選中のみ表示
6. **結果表示エリア** — 抽選後に大きく表示
7. **履歴**（折りたたみ）
8. **設定**（歯車アイコン／モーダル）

---

## 6. 非機能要件

| 項目             | 要件                                                                       |
| ---------------- | -------------------------------------------------------------------------- |
| 構成             | **バックエンド不要の静的サイト**。サーバへのデータ送信を一切行わない       |
| 技術スタック     | Vite + React + TypeScript + Tailwind CSS                                   |
| データ保存       | localStorage のみ                                                          |
| 対応環境         | モバイルファースト。iOS Safari / Android Chrome / PC Chrome                |
| 操作性           | **片手・親指操作**を想定。主要ボタンのタップ領域は44px以上                 |
| 配色             | ダークテーマを基調とする（配信画面に映えるため）。結果表示は高コントラスト |
| パフォーマンス   | 初回読み込み後はオフラインで動作可能                                       |
| アクセシビリティ | `prefers-reduced-motion` に対応。キーボード操作可                          |
| プライバシー     | 入力された名前は端末外に一切送信しない旨を画面上に明記                     |

## 9. Claude Code への実装指示（要約）

1. Vite + React + TypeScript + Tailwind のプロジェクトを新規作成
2. `src/data/pool.json` に第4章のスキーマでマスタデータを配置（初期はダミー語彙で可）
3. 抽選ロジックを `src/lib/draw.ts` に純関数として切り出す（重み付き抽選・連続重複回避を含む。テスト可能な形にする）
4. あみだくじの生成と経路解決を `src/lib/amida.ts` に純関数として分離する（横線生成、開始位置→到達位置の解決。DOM非依存でテスト可能にすること）
5. 演出時間の定数は `src/lib/timing.ts` に集約する（F-05のフェーズ内訳。合計4.0秒）
6. localStorage 操作を `src/lib/storage.ts` に集約
7. 第5章の画面構成でUIを実装。あみだくじの描画はSVGで行う
8. 結果表示の文字サイズは `clamp()` 等で可変にし、長い名前でも折り返して収まるようにする
